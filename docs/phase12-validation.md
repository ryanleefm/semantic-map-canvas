# Phase 12 验证说明（0.0.11）

状态：Phase 11、Phase 12 已获用户验收；正在准备 GitHub 测试版发布。

## 本阶段行为

普通节点和 group 的中央标题使用统一自适应排版：保留完整标题，自动换行，并按节点可用空间缩小。取消普通标题 96 字符截断、首行 2000 字符读取限制，以及 group 三行、省略号和 12px 最低字号。首个非空行的 Markdown 简化规则不变，不把整篇正文作为标题。空普通节点为 Untitled，空 group 为 Untitled group。

有空间时屏幕字号上限约 24px，空间不足则继续缩小。完整容纳不等于无限缩小仍然可读，极小节点或极长标题需要放大阅读。节点尺寸、原始内容、语义层级和 Canvas 文件不由字号适配逻辑修改。

## 实现与性能边界

- 浏览器按真实字体在 32px 基准字号下换行；批量写入标题和排版宽度后，批量读取布局，再批量写入缩放比例。宽度估计只决定换行形状，最终比例由实际布局测量决定。
- 使用 CSS transform 缩放整个文字块，保留居中和相对内边距，不受浏览器最小字号限制。不引入依赖、网络请求、额外定时器或逐字符测量。
- 缓存完整标题、节点宽高、字体版本和适配比例。同档位缩放仅计算比例和必要的 CSS 写入，不读取布局、不重新换行。约 300ms 的既有扫描检查标题及尺寸变化。
- 每个文档共用字体监听：根元素/body 的 class/style、head 样式内容与链接加载、FontFaceSet 加载事件会令缓存失效；下一次扫描重算。任意第三方插件仅通过 CSSOM insertRule 或单个节点样式改变字体而不触发上述事件，不保证即时识别。
- 删除、隐藏、暂停、切换画布、替换 DOM 和卸载时释放对应缓存与字体监听。尺寸无效时跳过辅助标题；恢复有效尺寸后自动恢复。
- 首次进入概括状态要创建和测量文字，数千节点仍可能短暂停顿；不承诺零开销或真实 Obsidian 帧率。

## 自动验证

- 94 项自动化测试通过：保留层级、嵌套、档位限制、编辑、存储、清理等回归，增加完整首行、缓存失效、无测量缩放、无效尺寸恢复和字体监听释放。
- 36 个隔离 Chrome 场景通过：浅/深主题 × 普通/group × 中文、无空格英文、混合 emoji、极小、宽扁、窄高、空标题、2400 字首行、零尺寸。
- 浏览器验证实际 Range 文字矩形落在标签区域内、居中、完整文本、字体改变及节点缩窄后的适配；测量计数验证缩放和稳定扫描不重复测量，无文本重写。
- 构建和 ESLint 通过。浏览器使用模拟的原生 Canvas DOM，不代表已完成真实 Obsidian UI 验收。

## 用户验收

1. 关闭再启用 Semantic Map Canvas，确认版本 0.0.11。
2. 打开 Semantic Map Canvas - Phase 12 - Ordinary.canvas。缩小到 STRUCTURE 或更远：该文件只有默认 L3 普通节点，因此 Phase 11 会保留 STRUCTURE。观察标题完整、居中、随着节点缩小而缩小。
3. 打开 Semantic Map Canvas - Phase 12 - Groups.canvas。缩小到 OVERVIEW 或更远，检查相同规则。普通与 group 文件包含中文、长英文、emoji、超长、空标题及宽扁/窄高节点。
4. 缩放往返并拖动节点边缘改变尺寸；编辑第一行或 group 名称；确认标题重新适配。切换浅深主题或字体后复查。
5. 在旧的嵌套/层级测试文件复查外层边缘标题、内层中央标题、逐级隐藏和最高层级档位限制。
6. 暂停语义显隐、切换 Canvas、关闭插件，确认原生内容和标题恢复。

本阶段不增加设置项，不迁移 schema v2，不修改用户已有语义属性。测试样例均为新文件。
