# Phase 10 验证与性能报告（0.0.9）

状态：Phase 1–10 已完成，用户确认现有功能满足要求。此文保留 Phase 10 的验证与性能记录，后续动态档位限制见 Phase 11。

## 本阶段交付

- 为包含关系增加几何缓存。位置、尺寸、类型、节点 ID、顺序或节点数量变化时重建；无几何变化时复用包含结果。
- 缓存仅保存几何值与节点 ID，不保存旧 DOM、编辑状态或层级；每次刷新仍使用当前节点对象。
- 切换 Canvas、暂停、卸载或运行时异常时清理缓存。
- 新增可复用性能基准和浏览器主题检查命令，不增加运行时依赖。
- 显隐规则、四级默认值、四档阈值和 schema v2 均不变。

## 性能方法与结果

环境：Windows，Node v22.11.0，AMD Ryzen 7 8845H。使用 linkedom 构造 Canvas DOM，真实调用 readRenderSnapshot、VisibilityController 和显隐规则。**不包含 Chromium 布局/绘制、Obsidian 本身渲染或第三方插件成本，不是帧率承诺。**

每种规模包含三层分组及普通内容，并有节点连线。各档位预热后记录 20 次稳定刷新；几何变化记录 10 次。p95 是样本中第 95 百分位，首次进入为单次测量。稳定刷新包括节点读取、几何校验、规则和 DOM 协调；zoom-only 不做完整扫描。

最终运行的稳定刷新耗时（毫秒）：

| 节点总数 / group 数 / 连线数 | STRUCTURE 中位 / p95 | OVERVIEW 中位 / p95 | MAP 中位 / p95 |
| --- | --- | --- | --- |
| 300 / 30 / 269 | 1.21 / 1.99 | 1.13 / 2.53 | 0.58 / 1.15 |
| 1500 / 150 / 1349 | 4.72 / 7.45 | 5.17 / 8.41 | 4.07 / 8.22 |
| 5000 / 500 / 4499 | 17.75 / 28.22 | 23.02 / 28.02 | 23.49 / 27.91 |

优化前同机 5000 节点稳定刷新中位数为 STRUCTURE 33.04ms、OVERVIEW 36.98ms、MAP 41.52ms。缓存显著减少稳定场景的重复计算；独立运行受 JIT、GC 和系统负载影响，不将差值视为固定比例保证。

5000 节点压力场景的进一步边界：
- 纯缩放更新 p95 约 0.01–2.46ms。
- 几何改变后重新计算的 p95 约 38.17–56.31ms。
- 首次进入 STRUCTURE 约 85.62ms（单次，涉及首次挂载大量标签），进入 OVERVIEW 约 40.31ms，进入 MAP 约 27.35ms。

因此不能宣称 5000 节点画布始终流畅，尤其首次进入和持续移动可能有停顿。当前改动针对稳定画布的重复计算；不在收尾阶段引入新的空间索引、分帧渲染或布局系统。更密集/更深的嵌套可能有更高成本。

## 在 Obsidian 中最终验收

1. 关闭再启用 **Semantic Map Canvas**，加载 0.0.9。
2. 打开已有 Phase 9 画布，保留之前设置的 L1 外层。逐步经过 DETAIL → STRUCTURE → OVERVIEW → MAP，再反向放大；确认各级退场、中央标题交接、连线同步隐藏仍正常。
3. 打开 **Semantic Map Canvas - Phase 10.canvas**。按画布说明将外层设为 L1，其余默认 group L2 / 普通节点 L3。
4. 分别切换 Obsidian 浅色/深色主题，检查短标题、长标题、空名称和小区域；检查边缘标题与中央标题转换。
5. 在 OVERVIEW 下调整 group 大小或移动内层，再用原生 undo/redo 恢复。确认缓存不会导致旧包含关系残留。
6. 修改普通节点层级、编辑普通内容或 group 名称，确认即使几何没有变化，显示仍更新。
7. 暂停/恢复语义显示、切换画布/普通笔记、关闭再启用插件，确认原生内容恢复，无重复标签。
8. 打开 **Semantic Map Canvas - Phase 10 - 300 nodes.canvas** 检查缩放与移动；需要更大规模时使用 **Semantic Map Canvas - Phase 10 - 1500 nodes.canvas**。这两张画布不预写元数据，普通节点 L3、group L2；MAP 未设 L1 时为空属于预期。
9. 最后确认既有画布的层级仍保留。Phase 10 不新增数据迁移，不改变原始布局。

以上真实窗口的主题、交互与性能体验仍需要用户确认，自动化通过不替代此验收。

## 现有边界和后续范围

- 仅活动 Canvas，使用 Obsidian 1.9.14 内部 API；未验证移动端或所有第三方主题/插件。
- 相同矩形、部分相交的 group 不做自动标签碰撞避让。
- 原生框选和空间索引不因视觉隐藏而改变，批量编辑可先暂停显隐。
- 同档位几何/编辑变化沿用约 300ms 检查，快速操作可能短暂延迟。
- 不包含节点尺寸预设、阈值设置面板、自定义 shortLabel UI、自动布局或公开发布。
- 本阶段不创建 GitHub Release，也不提交社区市场；发布前的兼容性和资料准备需单独安排。
