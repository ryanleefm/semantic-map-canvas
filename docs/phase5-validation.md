# Phase 5 验证说明（0.0.4）

## 在 Obsidian 中验收

1. 在测试 vault 中关闭再启用 Semantic Map Canvas。
2. 打开 **Semantic Map Canvas - Phase 5.canvas**。这是一张新增画布，未改动原有画布和已有层级记录。
3. 给“组外 L1”设为 L1、“组外 L3”设为 L3、“组内 L1”设为 L1，其余节点保持默认 L2。
4. 放大至 DETAIL：应看到全部节点、正文、连线。
5. 缩小到 STRUCTURE：L3 及连接它的线、箭头、连线标签消失；L1/L2 显示简短标签；group 标签保留原样。
6. 继续缩小到 OVERVIEW：保留 group 和组外 L1，组内 L1 也应隐藏。group 居中大标签留待 Phase 6。
7. 放大回 DETAIL：节点、正文和连线恢复，位置与尺寸不变。
8. 在 STRUCTURE 下将可见 L2 改成 L3，确认节点及时消失；放大或执行 Toggle semantic visibility 后可再次找到它。
9. 将“组内 L1”拖出 group 的边界，再缩小到 OVERVIEW，确认它因不再被 group 完全包含而显示。拖动操作是用户的正常 Canvas 编辑，插件不改布局。
10. 测试双击编辑、原生 undo/redo、切换画布、关闭再打开画布。编辑期间该节点保留完整正文。
11. 执行命令 **Semantic Map Canvas: Toggle semantic visibility**，应立即恢复全部节点；再次执行恢复语义显示。
12. 禁用插件后，确认辅助标签消失，原生正文、边框、连线和交互控件正常显示。

初次分类按 25% / 60%；之后缩小跨 58%、23%，放大跨 27%、62% 时切换。可在 Console 勾选 Verbose 并按 Semantic Map Canvas 过滤来确认档位。

## 已执行的自动化验证

33 项测试覆盖缩放状态机、存储与菜单回归，以及：
- 三种档位的节点与连线规则、group 完全包含关系。
- 组内节点移动后的重新判断、编辑状态例外、层级即时更新。
- HTML 字符串作为纯文本显示、标签来源与长度限制。
- 线条、箭头、连线标签、原生交互边框与选中工具条的同步显隐。
- 切换画布、暂停、禁用和 DETAIL 恢复时清理全部插件 CSS 类及标签。
- DOM 替换后清理旧元素，无变化时复用标签且无属性写入。
- 内部 API 读取异常后恢复原生显示并可自动恢复。
- 不写 Canvas 数据，渲染前后节点几何和连线数据序列化一致。

测试 DOM 使用 linkedom；不会运行真实 CSS 布局。用户已在真实 Obsidian 中验收通过 Phase 5。以上记录保留该阶段范围；group 中央标签在 Phase 6 实现。

## 实现边界

仅处理活动 Canvas；切走时恢复旧画布。显隐只影响视觉和 DOM 指针事件，不修改 Canvas 选择集合、空间索引或 undo 历史。原生框选仍可能包含视觉上隐藏的节点，批量编辑前可使用暂停命令。

原生 Canvas 会延迟挂载和替换元素，插件在同档位下以约 300ms 间隔检查；新元素或边框可能有短暂刷新延迟。很大的画布尚未做专门性能基准。group 中央大标签和节点默认尺寸均不属于本阶段。
