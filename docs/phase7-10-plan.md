# Phase 7–10 修改计划：统一层级与嵌套 group 语义缩放

状态：Phase 1–10 已完成并获用户认可。新增 Phase 11 动态显示限制已实现，0.0.10 待验收，见 phase11-validation.md。
本计划按用户要求分阶段执行；完成每阶段后提供测试结果及验收步骤，等待用户指令再进入下一阶段。Phase 7 验收步骤见 phase7-validation.md。

## 目标与共同规则

- 普通 text/file/link 节点及 group 均可设置 L1 Domain（领域）、L2 Core（核心）、L3 Structure（结构）、L4 Detail（细节）。
- 普通节点默认 L3，group 默认 L2。拖入、拖出或移动 group 不自动修改层级；外层 group 可手动设为 L1。
- 节点层级与缩放档位分别处理。普通节点在 DETAIL 显示完整内容，在其他档位若可见则显示简短标签。
- group 有原生容器（边缘标题）、概括（中央标题）、隐藏三种状态。有同等或更高优先级的可见内部对象时，外层 group 保持边缘标题。
- 准备概括的 group 可收起较低优先级的后代，但不能遮住同等或更高优先级的后代。编辑中的对象受保护，其祖先不以中央标题覆盖编辑区域。
- 隐藏 group 自身不自动隐藏全部后代；后代按自己的层级及可见祖先的概括关系决定显隐。
- 所有连线、箭头、连线标签按最终端点显隐同步处理。
- 不改 Canvas 坐标、尺寸、布局、原始标签及 undo 历史；元数据留在插件 data.json。暂停、禁用、切换画布和异常后恢复原生显示。

## 最终显示基线

下表为嵌套协调之前的候选状态。普通节点：详细=完整内容，简略=简短标签。group：详细=边缘标题，简略=中央标题。

| 档位 | L1 | L2 | L3 | L4 |
| --- | --- | --- | --- | --- |
| DETAIL | 详细 | 详细 | 详细 | 详细 |
| STRUCTURE | 普通节点简略 / group 详细 | 普通节点简略 / group 详细 | 简略 | 隐藏 |
| OVERVIEW | 普通节点简略 / group 详细 | 简略 | 隐藏 | 隐藏 |
| MAP | 简略 | 隐藏 | 隐藏 | 隐藏 |

group 的简略状态必须再经过嵌套协调：需要保留可见内部对象时，改用边缘标题。L4 延续直接从详细到隐藏的行为，不新增单独的 L4 简略档。

## Phase 7：四级属性、group 菜单及旧数据迁移

范围：
1. 扩展层级类型、菜单文案、合法值校验及按节点类型的默认值。
2. group 右键提供与普通节点一致的 Semantic level 菜单。
3. 迁移旧元数据：旧 L1→新 L2，旧 L2→新 L3，旧 L3→新 L4；保留路径、节点 ID、shortLabel。
4. 升级存储 schema，迁移前备份旧数据；迁移必须可重入，保存失败保留原数据并明确提示。
5. 暂以兼容规则保留普通节点现有显示：STRUCTURE 显示 L1–L3，OVERVIEW 显示组外 L1/L2；group 显示规则暂保持 Phase 6。明确此时 group 层级仅完成设置与持久化，Phase 8 才参与显隐。

验收：
- 普通节点与 group 都能设置四级并在重载后保持。
- 新普通节点为 L3，新 group 为 L2。
- 旧层级含义及已有 shortLabel 保留，重复重载不重复迁移。
- 原画布数据不变，迁移失败不会覆盖数据；原有缩放显示无意外回归。

交付：实现、迁移回归测试、测试 vault 构建及 Phase 7 验收说明。完成后停下等待验收/下一阶段指令。

## Phase 8：嵌套识别与三档 group 显示协调

范围：
1. 建立只读包含关系：使用完整矩形包含，部分重叠不算父子；相同矩形不互为父子，避免循环。需要直接父级时优先最小包含区域，并以稳定规则消除歧义。
2. 替换 OVERVIEW 中“所有 group 内普通节点一律隐藏”的旧规则，使用最终显示基线及祖先概括规则。
3. 在现有 DETAIL / STRUCTURE / OVERVIEW 三档中实现 group 的容器、概括、隐藏状态。
4. 从内向外协调标题：内层仍有可见重点时外层保持边缘标题；同为默认 L2 的嵌套 group 也不在同一条包含链上同时使用中央标题。
5. 处理隐藏容器中的可见子节点、编辑例外、移动/缩放 group 后重算，以及关联连线显隐。

验收：
- 外层 L1 + 内层 L2：OVERVIEW 外层边缘标题，内层中央标题。
- 外层 L2 + 内层 L2：外层边缘标题，内层中央标题。
- 三层以上嵌套遵守相同规则；空 group、同尺寸 group、部分重叠无循环或错误包含。
- 高优先级子节点不被低优先级祖先隐藏；正在编辑的内容保持可操作。
- 放大、暂停、禁用、切换、原生 undo/redo 后正确恢复。

边界：本阶段解决包含链上的中央标题冲突；任意交叠但不存在包含关系的 group 不做自动避让或重排。

交付：嵌套渲染实现、规则及 DOM 回归测试、嵌套测试画布与验收说明。完成后等待指令。

## Phase 9：MAP 全局档与四档切换

范围：
1. 增加 MAP 档，按最终显示基线只保留 L1 候选对象。
2. 初始建议阈值为 10%；运行中缩小至 9% 进入 MAP，放大至 11% 返回 OVERVIEW。现有 23%/27%、58%/62% 边界保留；根据真实体验在验收中调整。
3. 支持一次缩放跨越多个档位，明确首次打开时的分类；阈值附近不来回闪动。
4. 复用嵌套协调、编辑保护及字号补偿。只有手动设置了 L1 的对象才进入全局图；默认 L2 group 不自动晋升。
5. 更新诊断日志及使用说明，不在此阶段引入完整阈值设置面板。

验收：
- 外层 L1、内层 L2、普通节点 L3、补充节点 L4 依次收起。
- OVERVIEW 显示内层中央标题；MAP 隐藏内层并显示外层中央标题。
- 同级 L1 嵌套仍保持内层中央、外层边缘，避免重复居中。
- 大幅缩放、首次打开、边界反复滚动、返回 DETAIL 均正确。
- 没有 L1 的画布在 MAP 可能无语义对象显示，放大或暂停即可恢复；使用说明明确这一行为。

交付：四档状态机、回归测试、全局测试画布与验收说明。完成后等待指令。

## Phase 10：整体验证与文档收尾

范围：
1. 联合验证迁移、四级菜单、四档缩放、多层嵌套、编辑、连线及恢复路径。
2. 检查浅色/深色下标题可读性，测试长标题、空标题、小区域和边界情况。
3. 对代表性较大画布记录节点数、group 数及扫描耗时；仅在结果暴露问题时优化包含关系计算和缓存，避免每次缩放完整重建。
4. 检查无变化时不重复写 DOM；清理无效旧标签和类，确认无残留监听。
5. 更新 README、阶段验收记录、迁移及默认值说明。

验收：
- 自动化测试、TypeScript/正式构建、ESLint 通过。
- 测试 vault 中四级四档流程及恢复行为由用户验收。
- 明确实测环境及性能边界，不把模拟 DOM 检查作为真实 Obsidian 验收。
- 不增加节点尺寸预设、自动布局、任意标签碰撞避让、云服务或公开发布操作。
